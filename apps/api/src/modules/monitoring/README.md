# HLT-01 support integration proposal

## Staff follow-up workflow proposal — 4 November 2026

The authorized `feat/earl-hlt-01-follow-up-workflow` slice adds private assigned-officer follow-up tasks to dated support responses. Each dated immutable action creates one independent task, including existing dated actions during migration; a later response does not cancel an earlier commitment. Historical tasks mean completion has not been recorded, not that the member's concern remains unresolved. Task completion records an officer action and never resolves a loan, changes terms or publishes a private note to the member. Rescheduling requires a new calendar date and reason; completed tasks are terminal and a new dated response can create another task.

Proposed shared additions: strict follow-up/filter/event/page/detail and completion/reschedule schemas; `GET /support-follow-ups/queues/{state}`, `GET /support-follow-ups/{id}`, `GET /support-follow-ups/{id}/events`, `POST /support-follow-ups/{id}/completions` and `POST /support-follow-ups/{id}/reschedules`. The generator gains optional typed path-parameter metadata for the queue-state enum, retaining existing operation generation and UUID paging. Existing DTOs/routes stay unchanged. Robert reviews this additive contract/client/OpenAPI/controller-registration handoff; no receiving-owner approval is recorded by this proposal.

Tasks and their immutable events remain in monitoring. The existing response transaction creates the task atomically through a bounded owner trigger. A new additive migration supplies forced RLS, purpose-scoped views, append-only task/event records and a bounded transition function; runtime has no raw writes or raw private-table reads. Reads and transitions hold existing request-disclosure locks, checking the current assigned officer before any retry replay. Administrators retain assignment metadata only. Versions protect task transitions independently of request versions; command caches retain version receipts only, with original private results reconstructed from immutable events. Date validation occurs inside the new command, so a later same-key replay remains possible across calendar boundaries.

Queue states are all open, scheduled, due today, overdue and completed, evaluated using the server's Asia/Manila calendar date. Filters apply before pagination; stable task-ID order is explicit, with refresh for newly changed records. Detail history uses immutable version boundaries and bounded older pages. The staff support page adds a guarded Follow-ups view using shared controls, preserving drafts/uncertain commands, discarding obsolete reads and clearing private content on access denial. No member UI, servicing reader, financial write, external notification, AI ranking or weekly-capacity rule is added. Existing specs/design, owner brief, actual database/browser tests and screenshots provide implementation evidence; full HLT-01 acceptance remains separate.
