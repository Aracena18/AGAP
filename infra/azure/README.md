## Retention execution

`npm run evidence:retire -- manifest.json sha256 plan` checks an operator-supplied, checksum-bound per-source decision; `execute` performs it only after the specified date and with no active hold or worker lease. The manifest requires organization/source IDs, actual policy/approval/operator references, a worker-quiescence reference and `deleteNotBefore`. Quiesce the relevant workers and confirm all external I/O has stopped before execution; do not invent the institutional retention period. Active holds are maintained only by authorized operators, locking the same source row before changing a hold.

Execution first records a durable retirement and denies downloads/source confirmation, then removes original and all reserved derived-text objects outside database transactions and records completion. Rerun the identical manifest after an interrupted deletion. A different decision cannot silently replace it. This is file-content retirement; immutable financial facts, approved audit history and saved assessment snapshots follow their separately approved financial-record retention requirements. It does not claim to implement whole-member erasure. Reconcile and remove abandoned upload-intent/temporary objects only under an approved operator cleanup decision; they are never published as cleared sources.
