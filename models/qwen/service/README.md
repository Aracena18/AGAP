# Private Qwen extraction and fictional review service

`python3 -m models.qwen.service.server` runs one offline, bounded inference process. An accepted release enables the original pinned pretrained `/extract` capability. The separately checksum-bound [Experiment F candidate](../experiment_f/README.md) additionally enables `/review` only in the explicit fictional development pilot. Experiment D is never attached. Neither capability has financial tools, database credentials, document-download credentials or decision authority.

The API and worker keep the existing bearer-authenticated single Qwen transport. Use private HTTPS ingress, or explicit loopback HTTP in development. The model process defaults to `QWEN_BIND=127.0.0.1`, `QWEN_PORT=8080`; do not publish its listener. `/readyz` and `/healthz` also require the bearer token and return `ready`, enabled `capabilities`, `fictionalCandidate` and `baseDisabledParity`. No readiness is served until artifact/environment checks, GPU load and the candidate's real clean/disabled parity probe finish. Baseline-only deployments report parity as null because no adapter comparison was needed.

## Inputs and limits

- Common configuration: `QWEN_ARTIFACT_DIRECTORY`, `QWEN_EXPORT_MANIFEST_SHA256`, private `QWEN_SERVICE_TOKEN` of at least 32 characters. The process loads only the local verified base with offline mode and no remote code. An actual CUDA BF16 environment is required.
- Accepted baseline: `QWEN_RELEASE_FILE` / `QWEN_RELEASE_SHA256`, actual approved release and independent review reference. The service and Node adapter reject development-preview references and tuned artifacts on this path. Real records additionally require the separately approved institutional and real-record release controls.
- Fictional candidate: `QWEN_FICTIONAL_CANDIDATE_FILE` / `QWEN_FICTIONAL_CANDIDATE_SHA256`, `FICTIONAL_PILOT_ENABLED=true`, `EVIDENCE_RECORD_MODE=fictional`, non-production `NODE_ENV`. The record is explicitly `approved:false`; it cannot coexist with accepted-release inputs. No real or production candidate activation is permitted.
- `/extract`: `{page,text,provenance}`; exact 2,000-character page chunks, 4,096 input tokens, 2,048 output tokens. F is disabled through PEFT's context manager and restored even on failure. The Node adapter independently checks canonical schema, exact source, literal amounts/dates and gross/net support. It still limits documents to 32 chunks and 20 pages.
- `/review`: `{question,sources:[{source_id,quote}],provenance}`; 1–12 distinct exact excerpts, 1,536 total input tokens, 384 output tokens. It uses F's original first-attempt system/task prompt. Exceeding the total input budget rejects the whole request; no source is shortened or omitted. One format repair is allowed, with the same sources and remaining deadline. Output is the six-field untrusted F review object inside a guarded human-review/rejection envelope; it never becomes a financial fact automatically.

The canonical review schemas generate [review.schema.json](review.schema.json) and [review-input.schema.json](review-input.schema.json). Python reuses the existing fail-closed schema consumer and rejects duplicate JSON keys, unknown fields, invalid source IDs, altered quotes, forged verification/financial-authority flags and explicit lending decisions. Citation matching establishes only textual support; people still check meaning, completeness and authenticity. `NO_ISSUE` does not clear an application or omitted evidence.

Both endpoints share a nonblocking generation lock (`429 busy`) and a 90-second total request deadline. Generation must end with EOS before the token/deadline limit. A 95-second process watchdog handles wedged CUDA execution; deployment restarts the process and the application retains manual fallback. Startup has a separate ten-minute watchdog. Rejected raw model output and document content never enter operational logs. HTTP errors disclose only bounded machine codes.

## Build and actual verification

[Dockerfile.qwen](../../../infra/Dockerfile.qwen) is the pinned BF16/A100 recipe. Mount the imported artifact directory read-only, pass secrets only server-side, retain private loopback ingress and collect `/opt/runtime-freeze.txt` plus the built image digest. The supplied F export had unpinned runtime requirements; the chosen direct versions come from the earlier recorded export and require actual compatibility checks.

1. Import/check [F and the pinned base](../experiment_f/README.md); generate a checksum-bound fictional candidate without claiming independent acceptance.
2. Build the image in the authorized GPU environment and capture its exact freeze/digest. Startup must pass artifact checks, CUDA BF16 and clean/disabled parity.
3. With the server stopped, run `python3 -m models.qwen.service.compare --help` for the offline same-review-task clean-base/F/disabled comparison. Preserve failures, raw fictional outputs, latency/memory and actual model/runtime/provenance. Public development smoke is not independent evaluation or promotion.
4. Start the service and run `python3 -m models.qwen.service.smoke --candidate PATH --output NEW_DIRECTORY` using the token environment variable. This checks actual readiness and extraction/review/extraction transport behavior; it does not establish financial-semantic accuracy.
5. Exercise the actual application worker, source/version guards, staff review, corrections, renewed review and AI-unavailable manual fallback. Existing independent/model/institutional release criteria still govern any future promotion or real use.

The current local runtime has no usable NVIDIA/Python ML stack. Local importer, generated-schema, guard and simulated HTTP tests do not constitute successful GPU inference, independently accepted financial behavior or production hosting verification.
